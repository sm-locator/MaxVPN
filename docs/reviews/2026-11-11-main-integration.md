## Исправления по результатам обзора

1. **P1 — запуск VPN без авторизации.** В `POST /api/v1/vpn/start`
   добавлена проверка пользователя. Регрессионный тест проверяет ответ `401`
   и отсутствие вызова сервиса запуска; существующие тесты сохраняют проверку
   авторизованного запуска.
2. **P2 — неверная отметка применения правил.** Appliance теперь вычисляет
   отметку из того же снимка правил, который передаёт в runtime. Изменение
   правила во время применения остаётся ожидающим и обнаруживается следующим
   восстановлением. Проверяются изменение цели, включение/отключение,
   добавление и удаление правила.
3. **P2 — ошибки запросов в интерфейсе.** Опрос диагностики и изменение правил
   завершают состояние ожидания и показывают ошибку пользователю.
4. **Проверки frontend.** В CI добавлен отдельный запуск тестов, линтера и
   production-сборки React-приложения.
5. **P1 — унаследованный API клиентов без контроля доступа.** Все девять операций
   `/api/v1/clients` требуют администратора. Это общий набор WireGuard peers без
   владельца, поэтому политика соответствует `/servers`. Сохранены сценарии
   администратора; 36 отрицательных проверок используют реальные JWT/role checks
   и подтверждают отсутствие вызовов VPN, настроек и экспортёров при отказе.
6. **P2 — истечение сессии вне доменной диагностики.** Любой ответ `401` для
   текущего токена завершает сессию и очищает панель. Поздний ответ старого
   запроса не удаляет новый токен. Сетевой сбой оставляет сессию для повтора.
7. **P2 — оставшееся состояние диагностики после ошибки.** После отказа опроса
   удаляется устаревшее состояние наблюдения; диагностику можно запустить снова.
   Ответ после выхода из панели не возобновляет опрос.
8. **P2 — восстановление с пустым списком доменов.** В лаборатории обнаружен
   отказ повторного применения/boot restore для CIDR-only правил: UCI удаляет
   отсутствующий `.domain` с ошибкой. Теперь удаление выполняется при наличии
   опции; настоящая ошибка удаления по-прежнему прерывает применение.

## Проверки

Исходная контрольная точка имеет успешный
[запуск CI](https://github.com/sm-locator/MaxVPN/actions/runs/42954015193).
После исправлений успешно выполнены:

- Полный изолированный запуск итоговых Python-исправлений: **1164 backend и
  162 appliance**, успешно.
- Frontend: **69 unit/API-тестов и 6 браузерных сценариев Chromium**, линтер и
  production-сборка, успешно. CI выполняет чистый `npm ci` и оба набора.
- Проверка стиля изменённых Python API и нового регрессионного теста.

Браузерные сценарии используют настоящий React и управляемые ответы API:
истечение сессии при изменении правил и опросе диагностики, выход во время
запроса, обрыв и восстановление связи, повторный запуск диагностики, ошибки
изменения/удаления правил. Отдельный Vite-конфиг не имеет proxy к backend.
Два сценария авторизации и один состояния диагностики воспроизводили ошибки
до исправления; после исправления весь набор проходит. Результаты CI — в PR.

### Обновление существующей базы

Успешно выполнены upgrade, `pg_dump`, восстановление в другую временную базу
и повторный upgrade для данных head `main`, схемы с AWG/VLESS-профилями и
сохранённого локального дампа `0ffda25442bd`. Сравниваются все прежние строки,
столбцы и последовательности. В локальном дампе: 2 пользователя, 2 VPN-профиля,
51 правило, 3 группы, 5 связей. Пустые таблицы клиентов/серверов дополнительно
проверены синтетическими записями. Эти два синтетических прогона включены в CI.
Подробности и процедура выпуска: [upgrade-and-recovery.md](upgrade-and-recovery.md).

### Лабораторная сеть

Существующие образы OpenWrt запущены в copy-on-write VM с сетью только между
router/client/wan. Проверены реальный WAN IPv4/IPv6, VLESS, DIRECT, потеря TUN,
автовосстановление watchdog, firewall reload, reboot и возврат WAN. При
непрерывных LAN-пробах внешний QEMU pcap показал 0 пакетов к непомеченным
тестовым IPv4/IPv6 адресам в окнах потери туннеля, восстановления, reload и boot.
Добавлены средства запуска, сценарий, контрольные суммы и границы окон:
[openwrt-lab.md](openwrt-lab.md), [evidence](openwrt-lab-evidence.json).

Формат исходников проверяется через `git diff --check` с исключением вложенного
unified-патча sing-box: его обязательные пробелы контекста вызывают предупреждения
при проверке внешнего diff. Сам патч успешно разбирается `git apply --numstat`.

## Границы обзора и выпуск

Проверены авторизация новых backend API, цепочка новых миграций, применение
и восстановление маршрутов, обработка ошибок React и конфигурация CI.
Для большого исходного снимка выполнен выборочный обзор, а не полный аудит.
PR остаётся черновиком: на доступном образе отсутствуют WireGuard/AmneziaWG.
Локальный VLESS-прогон использовал поддерживаемый транспорт без REALITY.
Для закрытия обязательной матрицы нужны совместимый изолированный OpenWrt
с AmneziaWG и лабораторный peer, а также контролируемые REALITY/DNS/TLS
endpoint. Аппаратная платформа Brume 3 и внешние сервисы не проверялись.

Работа выполнялась в отдельной чистой копии. Локальные резервные файлы, `.env`,
ключи и рабочие базы в PR не добавлялись. Исходная ветка сохранена.

Новое подключение к рабочему Brume 3 и развёртывание не выполнялись. Слияние
интеграционной ветки в `main` выполняется отдельным решением после ревью.
