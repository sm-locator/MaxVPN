# Policy Engine Requirements

**Version:** 1.0 Draft

**Status:** Requirements Specification

**Applies to:** MaxVPN v0.3.0

---

# Purpose

Настоящий документ определяет функциональные требования к Policy Engine.

Все реализации должны соответствовать данным требованиям независимо от языка программирования, способа хранения данных или используемой VPN-технологии.

---

# Functional Scope

Policy Engine отвечает исключительно за принятие решений на основании заданного набора правил.

Он не отвечает за:

- выполнение маршрутизации;
- настройку VPN;
- изменение сетевой конфигурации;
- хранение правил;
- взаимодействие с Web API;
- работу с базой данных.

---

# Input

На вход Policy Engine получает два объекта.

## Routing Request

Описание сетевого соединения.

Например:

- Device
- Source IP
- Destination IP
- Destination Domain
- Protocol
- Port

---

## Rule Set

Упорядоченный список правил.

Порядок правил определяется пользователем.

Policy Engine никогда не изменяет порядок правил.

---

# Output

Результатом работы всегда является один объект.

```
Routing Decision
```

Он обязательно содержит:

- выбранную Policy;
- ссылку на правило, которое было применено (рекомендуется);
- признак использования Default Rule.

---

# Rule Structure

Каждое правило состоит из двух частей.

```
IF
    Conditions
THEN
    Policy
```

---

# Conditions

Одно правило может содержать одну или несколько Conditions.

Все Conditions внутри одного правила объединяются логическим оператором AND.

Например:

```
Device = Laptop

AND

Domain = github.com
```

Правило считается совпавшим только в случае выполнения всех Conditions.

---

# Rule Evaluation

Правила проверяются сверху вниз.

```
Rule 1

↓

Rule 2

↓

Rule 3

↓

Default Rule
```

После нахождения первого совпадения дальнейшая обработка прекращается.

---

# First Match Wins

Первое совпавшее правило имеет абсолютный приоритет.

Например:

```
Rule 1

Domain = youtube.com

Policy = DIRECT
```

```
Rule 2

Domain = youtube.com

Policy = VPN
```

Во время обработки будет применено Rule 1.

---

# Default Rule

Каждый Rule Set обязан содержать Default Rule.

Default Rule применяется только в случае, если ни одно другое правило не совпало.

Отсутствие Default Rule считается ошибкой конфигурации.

---

# Supported Conditions (v0.3)

Первая версия Policy Engine поддерживает следующие Conditions.

- Device
- Domain
- Domain Suffix
- Domain Keyword
- CIDR

Все остальные типы Conditions считаются расширениями будущих версий.

---

# Supported Policies (v0.3)

Поддерживаются только две политики.

```
DIRECT

VPN
```

BLOCK и другие политики появятся позже.

---

# Deterministic Behaviour

При одинаковом Routing Request и одинаковом Rule Set результат всегда должен быть одинаковым.

Использование случайных факторов запрещено.

---

# Side Effects

Policy Engine не должен изменять:

- правила;
- Routing Request;
- состояние системы.

Он является чистой функцией.

---

# Error Handling

Policy Engine должен корректно обрабатывать:

- пустой Rule Set;
- отсутствие Default Rule;
- неизвестный тип Policy;
- неизвестный тип Condition;
- некорректные данные Routing Request.

Ошибки должны возвращаться вызывающему компоненту.

---

# Extensibility Requirements

Добавление нового Condition не должно требовать изменения существующих Conditions.

Добавление новой Policy не должно требовать изменения существующих Policies.

Добавление нового Executor не должно требовать изменения Policy Engine.

---

# Performance Requirements

Policy Engine должен обеспечивать стабильную производительность при обработке больших Rule Set.

Алгоритмы поиска могут изменяться без изменения внешнего поведения системы.

---

# Compatibility

Все будущие версии должны сохранять совместимость с правилами, созданными в предыдущих версиях, если это явно не нарушает архитектурные ограничения.

---

# Acceptance Criteria

Policy Engine считается соответствующим требованиям, если выполняются следующие условия.

✓ Первое совпавшее правило всегда побеждает.

✓ Все Conditions внутри правила проверяются по принципу AND.

✓ Default Rule используется только при отсутствии других совпадений.

✓ Результат всегда содержит одну выбранную Policy.

✓ Поведение полностью детерминировано.

✓ Добавление новых Conditions не требует изменения существующего ядра.

✓ Добавление новых Policies не требует изменения существующего ядра.

✓ Policy Engine не зависит от инфраструктуры.

✓ Все требования подтверждаются автоматическими тестами.
