# Policy Engine Vision

**Version:** 1.0 Draft

**Status:** Architecture

**Applies to:** MaxVPN v0.3+

---

# Purpose

Policy Engine является центральной подсистемой MaxVPN.

Его задача — принимать единообразные, предсказуемые и расширяемые решения о том, как должен обрабатываться сетевой трафик.

Policy Engine не управляет VPN, не изменяет таблицы маршрутизации и не взаимодействует с операционной системой напрямую.

Он принимает решение.

Выполнение решения является задачей других компонентов системы.

---

# Mission

Пользователь должен описывать желаемое поведение сети, а не способ его реализации.

Вместо настройки VPN, маршрутов и низкоуровневых сетевых механизмов пользователь создаёт правила, описывающие требуемое поведение.

Например:

• Рабочий ноутбук → VPN

• Телевизор → DIRECT

• Холодильник → DIRECT

• YouTube → DIRECT

• Всё остальное → VPN

Policy Engine преобразует эти правила в единое решение.

---

# Core Principle

Любое сетевое решение принимается по одной схеме.

```
Routing Request
        │
        ▼
Conditions Evaluation
        │
        ▼
Policy Resolution
        │
        ▼
Routing Decision
```

Независимо от сложности системы алгоритм остаётся одинаковым.

---

# Separation of Responsibilities

Policy Engine отвечает только за выбор политики.

Он не знает:

- WireGuard
- AmneziaWG
- OpenVPN
- iptables
- nftables
- Linux Routing
- FastAPI
- Web UI
- Database

Это позволяет независимо развивать механизм принятия решений и инфраструктурные компоненты.

---

# Policy First

Внутри MaxVPN любое решение представлено политикой.

Policy определяет **что необходимо сделать**, но никогда не определяет **как именно это будет выполнено**.

Например:

DIRECT

VPN

BLOCK

В будущем:

VPN_HOME

VPN_WORK

VPN_BACKUP

CUSTOM

---

# Rules

Каждое правило состоит из двух частей.

```
IF
    Conditions
THEN
    Policy
```

Правило никогда не содержит информации о способе выполнения политики.

---

# Conditions

Conditions определяют, когда правило должно быть применено.

Примеры:

- Device
- Domain
- Domain Suffix
- Domain Keyword
- CIDR
- Port
- Protocol

В будущем:

- Country
- Time
- Application
- User
- Device Group
- Domain Group

Все условия являются равноправными.

Policy Engine не выделяет отдельные типы условий.

---

# Routing Request

Routing Request представляет описание конкретного сетевого соединения.

Он может содержать:

- Device
- MAC Address
- Source IP
- Destination IP
- Destination Domain
- Protocol
- Port

Не все поля являются обязательными.

Каждое условие использует только необходимые ему данные.

---

# Routing Decision

Результатом работы Policy Engine всегда является одно решение.

```
Routing Decision

↓

Policy
```

Policy Engine никогда не возвращает несколько решений.

---

# Deterministic Behaviour

При одинаковом наборе правил и одинаковом Routing Request результат всегда должен быть одинаковым.

Это одно из фундаментальных требований системы.

---

# Extensibility

Новые возможности должны добавляться без изменения существующего ядра.

Развитие системы происходит тремя способами.

### Новый Condition

Например:

Country

---

### Новая Policy

Например:

VPN_WORK

---

### Новый Executor

Например:

OpenVPN Executor

Policy Engine при этом остаётся неизменным.

---

# Independence

Policy Engine не зависит:

- от VPN-протокола;
- от операционной системы;
- от пользовательского интерфейса;
- от базы данных.

Он представляет собой независимую доменную подсистему.

---

# Long-term Vision

Policy Engine проектируется как универсальный механизм принятия решений для управления сетевым трафиком.

Маршрутизация через VPN является лишь одним из вариантов применения выбранной политики.

В дальнейшем Policy Engine может использоваться для:

- выбора VPN;
- прямой маршрутизации;
- блокировки соединений;
- применения различных сетевых политик;
- поддержки нескольких VPN-провайдеров;
- расширения функциональности без изменения архитектурного ядра.

---

# Design Principles

При разработке Policy Engine соблюдаются следующие принципы.

• Single Responsibility

Каждый компонент выполняет только одну задачу.

---

• Open / Closed Principle

Новые возможности добавляются расширением существующей архитектуры.

---

• Dependency Inversion

Ядро системы не зависит от инфраструктуры.

---

• Testability

Каждый компонент может тестироваться независимо.

---

• Predictability

Одинаковые входные данные всегда приводят к одинаковому результату.

---

# Architectural Statement

Policy Engine является интеллектуальным ядром MaxVPN.

Он отвечает не за выполнение сетевых операций, а за принятие решений.

Все остальные компоненты системы существуют для подготовки входных данных или выполнения решений, принятых Policy Engine.
