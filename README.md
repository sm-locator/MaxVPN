## Изолированный запуск тестов

В WSL2 или Linux с Docker Engine и Docker Compose v2 выполните `make test-docker`.
Команда собирает отдельный образ, создаёт временный PostgreSQL 17 в закрытой сети,
применяет миграции и запускает тесты backend и appliance. По завершении временные
контейнеры, сеть и образ удаляются. Рабочий Compose для этого запуска не нужен.

В тесты попадают текущие версии файлов, учтённых Git. Чтобы включить новый файл,
добавьте его в индекс. `PYTEST_ARGS` передаёт дополнительные аргументы тестам
backend, например `make test-docker PYTEST_ARGS="-k smart_routing"`. При
необходимости можно использовать уже собранный тестовый образ через
`MAXVPN_TEST_IMAGE`. CI выполняет ту же команду.


## Проверка переключения на стенде OpenWrt

Используйте отдельную VM или тестовый роутер с той же версией OpenWrt и тем же
firewall, что и на целевом устройстве. Подключите LAN-клиент и отдельный узел
наблюдения на тестовом WAN без выхода в рабочую сеть. Установите на стенд
согласованные версии скриптов и appliance. Для остановки VLESS appliance
требуется helper /usr/bin/vpn-lan-vless-stop из комплекта скриптов MaxVPN.

Снимайте трафик на тестовом WAN, пока LAN-клиент отправляет IPv4 и IPv6.
Проверьте сбой туннеля, откат, перезапуск firewall и одновременные команды
остановки и включения VLESS. Во время перехода и при сбое обычные LAN-пакеты
не должны выходить в WAN. Штатный WAN должен открыться после подтверждения
перехода, а в стабильном VPN-режиме на WAN допустимы только предусмотренные
политикой исключения. Сохраните версию прошивки, команды и результаты захвата.
